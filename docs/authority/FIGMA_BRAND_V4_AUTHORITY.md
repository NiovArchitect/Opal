## 1. Approved Figma is absolute presentation authority

For an existing approved destination, **runtime reconciles toward Figma**, not Figma toward runtime.

Figma is **not**: inspiration, mood board, guideline, “approximately what we want,” or something agents may adapt because code is easier another way.

It is the **measurement authority**.

Where represented, reconcile:

location · dimensions · spacing · typography · line height · weight · radii · strokes · opacity · gradients · color · image crop · asset choice · layering · component scale · hierarchy · controls · chrome · dock relationship · safe areas · scroll behavior · sheet geometry

And the **emotional composition** of the screen. Same buttons with lost visual tension, anticipation, intimacy, or focus = failed parity.

Formal parity package:

```
FIGMA + RUNTIME + OVERLAY + DIFF + OBJECTIVE NOTES
```

Do **not** mark GREEN because something “looks close” or is “visually similar.”

## 2. Brand V4 is the generative law when Figma does not literally show something

## 5. Parity methodology (Wave B squares)

Before editing a surface (e.g. Full Live `863:2`):

1. Write a short **intent lock** from Figma (focal point, first attention, hierarchy, immediacy, Brand V4 cues, role semantics, next action, depth, reward moment) — preserves psychology; does **not** grant design freedom  
2. Capture fresh approved Figma  
3. Capture runtime at exact viewport  
4. Overlay + diff  
5. Classify objective mismatches (geometry, typography, paint, asset, depth, hierarchy, state, behavior)  
6. Fix only actual discrepancies  
7. Re-capture until evidence supports GREEN or identify objective blocker  

Do not redesign. Do not stop at “looks better.”
