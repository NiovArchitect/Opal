## 1. Fundamental thesis

Opal is **not merely** a messaging app, event planner, recommendation engine, chatbot, calendar, social feed, travel app, group coordinator, dating app, or discovery app. Those may become capabilities.

Opal is an **intelligent social and experiential operating layer**.

Its job is to reduce the distance between:

```
ambiguity → understanding → alignment → possibility → decision
  → coordination → real-world action → experience → memory
  → stronger future intelligence
```

**North star: SPEED TO AUTHENTIC ALIGNMENT** — not raw session length, not compulsive engagement.

Optimize for **quality of alignment** and **quality of resulting life experience**.

Alignment is broader than scheduling. It can include emotional, social, preference, timing, location, cost, energy, comfort, relationship/family/romantic/travel context, intention, availability, dietary and entertainment preferences, accessibility, transportation, atmosphere, spontaneity, safety, budget, shared and individual history, what someone does **not** want, what previously worked or failed, shared goals, immediate opportunity, and longer-term possibility — always under consent and permission boundaries.

## 2. Core compounding loop

Primary product loop (compatible with `OPAL_PRODUCT_LOOP.md`):

```
CONVERSATION
  → SIGNAL EXTRACTION
  → CONTEXTUAL UNDERSTANDING
  → GRAPH / MEMORY UPDATE
  → ALIGNMENT DETECTION
  → RELEVANT POSSIBILITY
  → LOW-FRICTION DECISION
  → JOURNEY / REAL-WORLD COORDINATION
  → EXPERIENCE
  → OUTCOME SIGNAL
  → MEMORY
  → BETTER FUTURE ALIGNMENT
```

Every completed loop should make later loops faster, more relevant, more personal, less repetitive, easier to initiate, and easier to coordinate.

**Compounding intelligence law:** extend, reuse, compose, migrate carefully, preserve semantics.  
Avoid replace, parallel implementation, duplicate state, hardcoded demo paths, and fixtures that bypass domain reality.

---

## 3. Less UI work as intelligence increases

**MORE INTELLIGENCE SHOULD GENERALLY CREATE LESS USER WORK.**

Ideal user burden:

- **0 actions** — Opal surfaces the right thing  
- **1 confirmation** — “Yes, that's right.”  
- **1 correction** — “Not tonight, tomorrow.”  
- **1 private choice** — “I'd go.”

Do not respond to capability growth with more forms, repetitive questionnaires, re-asking known WHO/WHEN/WHERE, or multi-screen setup when context already answers.

The AI carries complexity. The interface exposes simplicity.

---

## 4. Solo mode is first-class

Never architect Opal as though value begins only after multiple friends participate.

A single person must get enormous value immediately (new city alone, free hours nearby, dinner, nightlife, travel, family-appropriate solo, wellness day, inexpensive exploration, full-day curation).

Solo and group are **two expressions of the same intelligence system** — not separate recommendation brains.

Solo utility strengthens network effects: users do not wait for graph density before magic appears.

---

## 5. Group and combination intelligence

Group curation is **not** averaging preferences. Search for genuine fit.

Preserve individuals inside group optimization. Output should feel “this works for **us**,” not “mathematical midpoint.”

**Combination intelligence is first-class:** preferences with one friend, a partner, a child, three friends, or alone may produce entirely different ideal experiences. Learn combinations over static preference vectors where permitted.

---

## 6. Conversation is an intelligence surface

Chats are not merely message containers. Conversation is a primary source of consensually usable contextual signal (people, places, plans, timing, interests, constraints, commitment state, cancellations, etc.).

**Confidence layers** (do not treat every sentence as permanent truth):

| Layer | Meaning |
|-------|---------|
| EXPLICIT | User directly stated it |
| OBSERVED | User repeatedly chose or did it |
| INFERRED | Evidence exists; uncertainty remains |
| SHARED | Multiple participants/contexts support it |
| TEMPORARY | Moment-relevant only |
| HISTORICAL | Previously true; not assumed current |
| DISCONFIRMED | Prior assumption is wrong |

User correction overrides inference. Explicit > weak inference. Sensitive inference must not silently become permanent profile truth.

---

## 7. Outcome learning and negative intelligence

Do not learn only from what users **say** they like. Where appropriate and permitted, learn from outcomes: accept/reject/ignore, destination changes, join/cancel, completion, repeats, category losses, explicit feedback.

Preserve uncertainty — not going somewhere can mean bad fit, timing, friend cancel, price, weather, energy, transport, etc.

**Negative intelligence compounds too.** What users do not want (too expensive, too loud, too far, no nightclubs, dietary, crowds, alcohol-centered, already went) is valuable. Stop repeating rejected patterns without reason.

---

## 8. Experience curation can span the journey

Curation may eventually cover sequences (date night arcs, family days, solo destination days, group nights) — not only isolated venue cards.

Offer a strong path. Allow correction. Recompute intelligently. Do not force users to rebuild an entire plan because one component changed. Preserve agency.

---

## 9. Network effects (defensible form)

1. **People** — more participating friends → more possible alignment  
2. **Context** — more consented history → better relevance  
3. **Experience memory** — more completed Journeys → stronger prediction  
4. **Group knowledge** — combinations of people, not only individuals  
5. **Local possibility** — trusted people interested/going/nearby/available  
6. **Reduced friction** — as intelligence compounds, effort to create the next successful experience decreases  

Defensible network effect:

> **More relationships + more successful experiences + more contextual history = less effort required to create the next successful experience.**

The product gets **easier** as it gets smarter.

## 13. Never collapse Opal into a chatbot

Global Opal is not “ChatGPT inside the app.” Intelligence appears across ranked possibilities, contextual cards, timely prompts, Graphs, Journeys, memory, smart defaults, and correction handling. The most magical intelligence may appear **without** a chat exchange.

## 14. AI confidence / permission / privacy

User should feel: **“Opal understands me.”** Not: **“Opal is watching me.”**
