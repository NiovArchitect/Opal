## Purpose

Define the missing **time + place + context** dimension so future intelligence does not flatten humans into static profiles.

Opal must understand:

> **People + Relationships + Context + Time + Location + Intent**

Recommendations are an **output**. The product is a **context engine** that helps humans move toward alignment.

> Opal builds a constantly updated understanding of the situation around humans and helps them move toward alignment.

Humans are not only “what they like.”  
Humans are **what matters right now, with these people, in this place, for this reason.**

## Core law

A person is not one fixed state.

| Layer | Contents |
|-------|----------|
| **Stable identity** | Values · personality tendencies · core preferences · boundaries · principles |
| **Dynamic context** | Who they are with · where · when · situation · needs · emotional/social context |

Both are true. Neither cancels the other.

## Human context model

Do **not** model: `Person → Facts`.

Model:

```text
Person
 ├── Core Identity
 ├── Contexts
 ├── Relationships
 ├── Experiences
 ├── Current State
 └── Future Intentions
```

### Context expressions (same person, valid differences)

| Context | Possible expressions |
|---------|----------------------|
| Partner | Romance · dates · shared activities · future planning |
| Child | Teaching · protection · responsibility |
| Family | Traditions · gatherings · support |
| Church / community | Service · fellowship · shared values |
| Work | Productivity · professionalism · collaboration |
| Alone | Coding · reflection · personal growth |
| Stranger / new connection | Discovery · curiosity · networking |

These do not contradict. They are contextual expressions of one person.

## Temporal model — Past → Present → Future

| Time | Represents | Rule |
|------|------------|------|
| **Past** | Completed experiences · history · lessons · (future permissioned memory) | Informs · does not control |
| **Present** | Availability · location · situation · needs | Highest relevance for immediate action |
| **Future** | Intentions · plans · possibilities · commitments | Distinguish Interested≠Committed · Suggested≠Accepted · Discussed≠Planned |

## Location model

Location is not only coordinates. Location provides context.

```text
Location + Time + People + Intent = Situation
```

Examples of the same person: home (rest/family) · work (professional) · vacation (exploration) · church (community) · restaurant (social/dining).

## Alignment Engine concept (future — not YOU knobs)

**Not:** Find what one person likes.  
**Instead:** Find the highest alignment opportunity between people, place, time, and intent.

```text
Inputs: People · Relationships · Preferences · Constraints · Location · Time
        · Availability · Past experiences · Current context · Future intentions
        ↓
Alignment Engine
        ↓
Output: Suggestion · Preparation · Coordination · Action
```

### Gyroscope principle

Opal balances **contextual reality** — not “whose preference wins.”

Like a gyroscope maintaining orientation under multiple forces: find **stable alignment**.

Example: A loves adventure; B prefers relaxed → coastal walk + dinner can satisfy both contexts given location, timing, past enjoyment, and constraints.

### Group alignment

Groups are not averages. Groups are temporary social contexts.

```text
Individual Preferences + Relationship Dynamics + Group Intent
+ Constraints + Location + Time = Group Alignment
```

Find workable overlap — not the mean preference.

### Current state layer

```text
Historical Pattern + Current State = Current Recommendation
```

Long-term “loves going out” + today tired/stressed → do not blindly optimize the pattern.

## Accuracy principle

Opal improves accuracy by increasing **correct context**, not unlimited data collection.

Accuracy requires: correct source · scope · time · relationship · permission · correction ability.
