# Solo and Group Location Alignment — Gap (Grok)

**Author:** Grok  
**Status:** Architecture gap audit only — location not live

## Role of location

Location reduces **real-world friction**. It is not the product. Alignment remains social and permissioned.

## Modes (target, not implemented)

| Mode | Use | Default |
|------|-----|---------|
| Private ranking only | Rank without sharing location | Preferred |
| This experience only | Scoped to one opportunity | Preferred for groups |
| Approximate area | Neighborhood-level | Shared-safe possible |
| ETA only | Travel feasibility | Shareable |
| Selected sharing | Explicit user action | Opt-in |
| Precise | Arrival, navigation handoff | Only when required + approved |

**No continuous precise tracking by default.**

## Solo traveler gap

Needed inputs (permissioned): time, approximate area, weather, mood, budget, walking tolerance, past outcomes.  
Needed output: ≤3 options, one preferred, simple explanation.  
**Current:** absent as product loop.

## Group location gap

Needed: centrality, backtracking avoidance, multi-origin meet points, traffic/parking/transit as soft factors, private “cannot go far” without public shame.  
**Current:** synthetic collective fit may encode travel balance in fixtures; no live location pipeline.

## Privacy non-leak (must hold)

Shared explanation: “This place is easier for everyone.”  
Forbidden: “Person B can’t afford travel / lives too far” as shared reason.
